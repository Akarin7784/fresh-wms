## 1. 职责与边界

### 1.1 负责
1. **复核**：出库单拣货完成（04 `PICKED`）后，由**非拣货人**逐行扫码核数。通过后推进 04 T12 `PICKED → CHECKED`；不通过则走 T13（退回拣货差异处理）。
2. **装箱**：复核通过后把货装入箱（`pack_box`）或周转筐，封箱打印箱码。
3. **集货**：封箱的箱放入集货位，推进 04 T14 `CHECKED → STAGED`。
4. **发货出库（交接）**：按车次组 `shipment`，把 STAGED 箱挂上车次，主管/发货员确认交接：箱 `SHIPPED`、出库单 T16 `STAGED → SHIPPED`、`post_event(SHIP)`，写 outbox 通知 11 回传上游，调用 16 `WaybillService.create_from_shipment(shipment_id)` 生成运单。

### 1.2 不负责
- 装车扫码、缺箱放行、发车、在途、签收、拒收回仓：全部归 **16**（`waybill`、`waybill_stop`、`pod`、`pod_op`）。本篇在 `shipment.status = HANDED_OVER` 处交出。司机、车辆、发车时间、签收都只在 16 的 `waybill` / `waybill_stop` / `pod` 上；签收（POD）按**出库单**粒度记在 16（16 Δ1），`shipment` 不存这些列，只用 `waybill_id` 指向 16 的运单。
- `outbound_order.delivery_result` 由 04/16 维护；拒收货经 10 退货入库。
- 库存扣减：已在拣货确认时由 05 `consume` 完成（02 UC5）。本篇发货只写 `post_event(SHIP)`（direction=0，不改 `on_hand`，02 UC7）。
- 签收更正：只走 12 审批，本篇不涉及。

### 1.3 与原文档的差异
| # | 原文档 | 本篇 | 原因 |
|---|---|---|---|
| Δ1 | `shipment.status` 含 `LOADING/DEPARTED/DELIVERING/SIGNED/CLOSED` | 本篇只有 `CREATED / HANDED_OVER / CANCELLED`，后续状态在 16 `waybill` | 与 16 Δ1 一致，避免两边重复维护状态 |
| Δ2 | 复核结果只记在 `outbound_order.checker_id` | 新增 `check_record / check_line / check_op` | 需要逐扫去重、差异留痕、SoD 在库层兜底 |
| Δ3 | `pack_box.sealed` 布尔 | 增加 `status`，`sealed` 保留并由 CHECK 约束与状态一致 | 箱有集货、发货阶段，封箱后要冻结明细 |

## 3. 领域模型

### 3.1 复核单 `CheckRecord`
一张出库单同一时刻至多一张 `OPEN` 复核单（`uq_chk_open`，部分唯一）。开单时冻结：`picker_id`（取 `outbound_order.picker_id`）、各行 `expected_qty_milli`（= 出库行 `picked_qty_milli`）。之后拣货侧再变（如撤销拣货）不影响本单；04 状态守卫保证复核期间出库单停在 `PICKED`，撤销拣货需先作废复核单。

### 3.2 复核扫描 `CheckOp`
与 05 `pick_op` 同构：PDA 四元键 `(check_id, line_no, device_instance_id, op_seq)`，`op_type ∈ {SCAN, UNDO}`。逐件模式另有 `scan_event_id`。条码按 SKU 主数据（`sku_barcode`）现场校验，错码返回 42210，`check_op.result_code='42210'`。复核不动库存，所以 `check_op` 是这条操作的唯一账。

### 3.3 箱 `PackBox`
箱属于一张出库单（`outbound_id`），挂在一张 `PASSED` 复核单上（`check_id`，应用层校验）。一单多箱；同一箱不跨单（冷链按单配送，跨单拼箱见 Q5）。箱明细 `pack_box_line(box_id, sku_id, lot_id)` 唯一。

**装箱数量守恒**（应用层，提交封箱时校验）：某出库单所有非 `CANCELLED` 箱的明细合计，按 `(sku_id, lot_id)` 等于复核通过量。不等返回 42211 `CHECK_QTY_MISMATCH`，`detail = {sku_id, lot_id, checked_qty, packed_qty}`。

### 3.4 车次 `Shipment`
一个车次装多张出库单（`shipment_order`），多个箱（`pack_box.shipment_id`）。交接时冻结 `box_count`，16 据此生成运单的箱码白名单。

## 4. 涉及的表

### 4.1 `check_record`（新增）
| 列 | 说明 |
|---|---|
| id / code | 雪花 ID；单号 `CHK-{仓}-{节点}-{作业日}-{序号}`（00 §6.2），`uq_chk_code` |
| warehouse_id / outbound_id | |
| picker_id | 展示用（主拣货人）；`ck_chk_sod` 只是简单兜底，**SoD 以 `check_picker` 为准**（H1） |
| checker_id | 复核人，开单后不可改 |
| status | `OPEN / PASSED / FAILED / CANCELLED`（`ck_chk_status`） |
| mismatch_count | 不符行数；`ck_chk_pass`：PASSED 时必须为 0 |
| closed_by / closed_at | `ck_chk_closed`：OPEN 时两者为空，非 OPEN 时两者非空 |
| version | 乐观锁 |

触发器 `trg_chk_*`（两库）：
- **INSERT 只能是 OPEN**（`check_state`，H2）。
- **转 PASSED**（H2）：至少有一行复核行，没有 `checked_qty_milli <> expected_qty_milli` 的行，且至少登记了一个拣货人；否则 `check_not_complete`。不再依赖应用写的 `mismatch_count`。
- 关单后任何列不可改（`check_closed`）；`outbound_id / checker_id / picker_id / code` 不可改，不可删，PG 不可 TRUNCATE（`check_immutable`）。
- SQLite `BEFORE INSERT`：id、code 已存在或同一出库单已有 OPEN 单时报 `check_duplicate`，挡住 `INSERT OR REPLACE` 和 UPSERT。

### 4.1a `check_picker`（新增，H1）
`(check_id, user_id)` 主键，外键到 `check_record`。开单时同一事务写入该出库单**所有拣货人**：全部 `pick_task.assigned_to`（含改派前的持有人），以及该单 `pick_op` / 拣货流水上出现过的操作人。只追加：不可改、不可删、PG 不可 TRUNCATE（`check_immutable`）；复核单非 OPEN 时不可再插（`check_closed`）。
**SoD**：`user_id = check_record.checker_id` 的插入被拦（`check_sod`）。应用层开单时先比对，命中返回 **40312** `SOD_VIOLATION`，`detail = {reason: "CHECK_SOD", checker_id, picker_ids[]}`。拣货人为空的单不能复核通过（PASSED 要求至少一个拣货人）。

### 4.2 `check_line`（新增）
`check_id` 外键到 `check_record`；`uq_chkl_line(check_id, line_no)`、`uq_chkl_obl(check_id, outbound_line_id)`；`ck_chkl_qty`：`0 ≤ checked ≤ expected`，均为整数 milli。多扫在应用层返回 42214 `OVER_QTY`，`detail.reason = OVER_CHECK`，库层 CHECK 兜底。复核单 OPEN 时才能插入或更新（`check_closed`）；`expected_qty_milli` 等身份列不可改，不可删（`check_immutable`）。

### 4.3 `check_op`（新增）
| 列 | 说明 |
|---|---|
| check_id, line_no, device_instance_id, op_seq | 四元键，`uq_check_op` |
| op_type | `SCAN / UNDO`（`ck_check_op_type`） |
| barcode / qty_milli | `ck_check_op_qty`：`> 0` 整数 |
| scan_event_id | 逐件模式；`uq_check_op_scan(check_id, scan_event_id)` 部分唯一 |
| result_code / finished_at | 成功为 NULL，失败为 5 位码（`ck_check_op_result`，如 42210、42214）；`ck_check_op_finish`：未完成不能有 result_code；只写一次 |

`trg_check_op_*`：`finished_at` 非空后整行冻结，身份列不可改，不可删，PG 不可 TRUNCATE（`check_op_immutable`）。SQLite `BEFORE INSERT` 报 `check_op_duplicate`。`wms_app` 只有 `SELECT, INSERT` 加列级 `UPDATE (result_code, finished_at)`。

### 4.4 `pack_box`（改）
新增 `check_id`（外键 `check_record`）、`status`、`shipped_at`、`voided_at`、`version`、`created_at`；`shipment_id` 加外键 `shipment`；`weight_g` 改 `BIGINT` 整数克（Q6）。
- `ck_box_status`：`OPEN / SEALED / STAGED / SHIPPED / CANCELLED / VOIDED`
- `ck_box_sealed`：`OPEN / CANCELLED ⇔ sealed=false`；`SEALED / STAGED / SHIPPED / VOIDED ⇒ sealed=true` 且 `packed_at`、`checker_id`、`check_id` 非空
- `ck_box_staged`：`STAGED / SHIPPED` 必须有 `stage_location_id`；`ck_box_shipped`：`SHIPPED` 必须有 `shipment_id`、`shipped_at`；`ck_box_voided`：`VOIDED ⇔ voided_at` 非空；`ck_box_weight`：`weight_g >= 0`
- 索引 `ix_box_outbound(outbound_id, status)`、`ix_box_shipment(shipment_id)`、`ix_box_check(check_id)`

触发器 `trg_box_*`（两库）：
| 规则 | 库层报错 | 接口码 |
|---|---|---|
| INSERT 只能 OPEN（H6） | `box_state` | 40930 |
| 状态边只能按 §5.2 走 | `box_state` | 40930 |
| `SHIPPED / CANCELLED / VOIDED` 整行只读（H6） | `box_closed` | 40930 |
| `code / outbound_id / warehouse_id` 不可改；不可删；PG 不可 TRUNCATE | `box_immutable` | 50010 |
| 封箱后（新旧状态都不是 OPEN）`check_id / checker_id / packed_at / weight_g` 不可改（H6） | `box_sealed` | **40937** BOX_SEALED_IMMUTABLE |
| OPEN→SEALED：`check_id` 指向**同一出库单**、状态 `PASSED` 的复核单（H3） | `box_check_invalid` | 40930 |
| OPEN→SEALED：`checker_id`（封箱人）= 复核单 `checker_id`（H3），没有权限例外 | `sealer_not_checker` | 40930 `detail.reason=SEALER_NOT_CHECKER` |
| OPEN→SEALED：该复核单下所有有效箱（含本箱，排除 CANCELLED/VOIDED）按 SKU 合计 ≤ 复核量（H3） | `box_over_check` | 42211 |
| `shipment_id` 只能在箱 STAGED、新旧车次都是 CREATED 时挂/摘；STAGED→SEALED 前须先摘车（H4/H6） | `box_shipment` | 40930 |
| STAGED→SHIPPED：车次已 HANDED_OVER（H4） | `box_shipment` | 40930 |
| SEALED→VOIDED：有一张 APPROVED 作废申请（Q8） | `box_void_unapproved` | 40930 |
SQLite `BEFORE INSERT` 报 `box_duplicate`。

### 4.4a `box_void_request`（新增，Q8）
| 列 | 说明 |
|---|---|
| box_id | 外键 `pack_box` |
| reason_code | `LOST / DAMAGED`（`ck_bvr_reason`） |
| remark / photo_ids | 备注；照片对象存储 key 的 JSON 数组 |
| requested_by / requested_at | 申请人 |
| status | `PENDING / APPROVED / REJECTED`（`ck_bvr_status`） |
| decided_by / decided_at | `ck_bvr_decided`：PENDING 时为空，否则非空；`ck_bvr_self`：`decided_by <> requested_by`（不能自批） |
`uq_bvr_pending`：一箱同时至多一张 PENDING。触发器：只能对 SEALED 箱申请（`box_void_state`）；只能 PENDING→APPROVED/REJECTED 一次，之后冻结（`bvr_closed`）；申请内容不可改、不可删（`bvr_immutable`）；SQLite 报 `bvr_duplicate`。

### 4.5 `pack_box_line`（改：加触发器）
`trg_box_line_*`：所属箱不是 `OPEN` 时，INSERT / UPDATE / DELETE 都报 `box_sealed`（接口 40937）；不能把行挪到别的箱。`wms_app` 现在有 DELETE 权限（小赵建议 2），触发器保证只有 OPEN 箱可删。

### 4.6 `shipment`（改）
状态收窄为 `CREATED / HANDED_OVER / CANCELLED`（`ck_shp_status`）；新增 `dock_location_id`、`waybill_id`（→ 16 `waybill.id`，1:1）、`box_count`、`handed_over_at`、`handed_over_by`、`version`。删除 `vehicle_no`、`driver_id / driver_name / driver_phone`、`planned_depart_at`、`departed_at`、`signed_at` 及索引 `ix_shp_driver`（Q7）：司机、车辆、发车、签收都在 16，签收（POD）按出库单记在 16。
- `ck_shp_handover`：`HANDED_OVER` 时 `handed_over_at / handed_over_by / waybill_id` 非空且 `box_count > 0`
- `trg_shp_*`（两库，H4）：INSERT 只能 CREATED；只允许 `CREATED → HANDED_OVER / CANCELLED`（`shipment_state`）；**CANCELLED 要求车次下没有箱、没有出库单**（`shipment_not_empty`）；**HANDED_OVER 要求 `box_count` = 本车次 STAGED 箱数**（`shipment_box_count`）；终态后 `status / box_count / waybill_id / handed_over_at` 冻结（`shipment_closed`）；不可删、PG 不可 TRUNCATE（`shipment_immutable`）；SQLite `BEFORE INSERT` 报 `shipment_duplicate`

**交接顺序**（与触发器配套）：箱 STAGED 时挂车 → 车次 `CREATED → HANDED_OVER`（核箱数）→ 箱 `STAGED → SHIPPED`（要求车次已交接），全在同一事务。

### 4.6a `shipment_order`（改，H5）
`shipment_id` 外键 `shipment`；新增 `uq_sho_outbound UNIQUE (outbound_id)`：一张出库单只能挂一个车次（车次取消前必须先摘单，所以不需要部分唯一）。触发器：任何 UPDATE 都拦（`shipment_order_immutable`，摘挂 = 删 + 插）；车次不是 CREATED 时 INSERT / DELETE 都拦（`shipment_closed`）；PG 不可 TRUNCATE；SQLite 报 `sho_duplicate`。

### 4.7 授权（`wms_app`，最小权限）
| 表 | 授权 |
|---|---|
| check_record, check_line, box_void_request | SELECT, INSERT, UPDATE |
| check_op | SELECT, INSERT, UPDATE(result_code, finished_at) |
| check_picker | SELECT, INSERT |
| pack_box, shipment | SELECT, INSERT, UPDATE |
| pack_box_line, shipment_order | SELECT, INSERT, UPDATE, DELETE（删除由触发器限定在箱 OPEN / 车次 CREATED） |

verify 的 `EXPECT_PRIVS` 已同步，按 pg_class 逐表核对，多给少给都失败。

### 4.8 写法规则（两库一致）
所有本篇新表和 `pack_box`、`shipment` 都用**普通 INSERT**，不用 `ON CONFLICT` / `INSERT OR REPLACE / OR IGNORE`。撞唯一键后在新事务里按键读回比对：`check_op` 比 `(op_type, barcode, qty_milli)`，全同 → 重放首次结果；不同 → 40910 `key_type=PDA_OP`。PG 撞键会中止当前事务，需要同事务时用 `SAVEPOINT` 包住这条 INSERT。

## 5. 状态机

### 5.1 复核单
```mermaid
stateDiagram-v2
  [*] --> OPEN: 开单（出库单 PICKED）
  OPEN --> PASSED: 全部行 checked = expected
  OPEN --> FAILED: 提交时有不符行
  OPEN --> CANCELLED: 主管作废（换人）
  PASSED --> [*]
  FAILED --> [*]
  CANCELLED --> [*]
```
- PASSED 同事务推进 04 T12 `PICKED → CHECKED`（条件更新 `WHERE status='PICKED'`，rowcount=0 → 40930）。
- FAILED 不改出库单状态；出库单留在 `PICKED`，差异按 04 T13/05 撤销拣货处理后重新开单。（04 T13 是 `CHECKED → PICKED`，用于集货前发现问题退回，见 §5.2。）
- 状态迁移依赖应用层条件更新 `WHERE id=:id AND status='OPEN' AND version=:v`；库层触发器只保证终态不可变。

### 5.2 箱
```mermaid
stateDiagram-v2
  [*] --> OPEN
  OPEN --> SEALED: 封箱（复核人本人；同单 PASSED 复核；不超复核量）
  OPEN --> CANCELLED: 空箱作废 / 拣货后取消
  SEALED --> OPEN: 解封（pack.unseal + audit_log）
  SEALED --> STAGED: 入集货位
  SEALED --> VOIDED: 丢失/破损作废（审批通过，Q8）
  STAGED --> SEALED: 移出集货位（须先摘车）
  STAGED --> SHIPPED: 发货交接（车次已 HANDED_OVER）
  SHIPPED --> [*]
  CANCELLED --> [*]
  VOIDED --> [*]
```
出库单全部有效箱 STAGED 后推进 04 T14 `CHECKED → STAGED`；有箱退回 SEALED 时走 T15 `STAGED → CHECKED`。拣货后取消时，箱若非 OPEN，先由主管解封再作废（应用层在同事务里完成）。

**作废箱（VOIDED）之后**：箱里的货不再计入装箱守恒（§3.3 合计排除 VOIDED）。出库单回到"差装箱"状态：可重新拣货补装（05 新任务），或主管按缺货走 04 拣后取消；丢失货品由 10 开异常单（EXC）跟进，本篇不改库存。只有 SEALED 箱能作废：OPEN 箱直接 CANCELLED；STAGED 箱先移出集货位；SHIPPED 后归 16。

### 5.3 车次
```mermaid
stateDiagram-v2
  [*] --> CREATED: 组车次
  CREATED --> HANDED_OVER: 发货交接
  CREATED --> CANCELLED: 撤销（未交接）
  HANDED_OVER --> [*]: 交给 16（waybill）
  CANCELLED --> [*]
```
交接后不能撤回。16 Q-B 已定：发车前不撤运单，只改派；真要退回走 06 红冲（见 Q4）。

## 6. 核心流程

### 6.1 复核扫码
```mermaid
sequenceDiagram
  participant P as PDA（复核员）
  participant API
  participant DB
  P->>API: POST /checks/{code}/scans {line_no, device_instance_id, op_seq, barcode, qty}
  API->>DB: INSERT check_op（普通 INSERT）
  alt 撞 uq_check_op / check_op_duplicate
    API->>DB: 读回已有行比对
    API-->>P: 同 → 重放首次结果；不同 → 40910 PDA_OP
  else 新操作
    API->>API: 条码 → SKU 校验（错 → 42210）
    API->>DB: UPDATE check_line SET checked=checked+:q, version=version+1 WHERE id=:l AND checked+:q<=expected
    alt rowcount=0
      API->>DB: UPDATE check_op SET result_code='42214', finished_at=now()
      API-->>P: 42214 OVER_QTY reason=OVER_CHECK
    else
      API->>DB: UPDATE check_op SET finished_at=now()
      API-->>P: 200 {checked_qty, expected_qty}
    end
  end
```
**过可售期拦截（已定规则，00 §6.4）**：扫码时按该行已拣批次查 `lot` 的可售天数 `sell_days`（第 9 篇口径）。批次已过可售期 → 本扫不计数，`check_op.result_code='42214'`，返回 42214 `OVER_QTY`，`detail = {reason: "SELL_EXPIRED", lot_id, lot_code, sell_deadline}`；复核单不能 PASSED，该行按 04 T20 拣后取消处理（生成 `return_record(CANCEL_AFTER_PICK)` + 系统冻结；货物再由第 9 篇按 `SELL_EXPIRED` 转损耗，`uq_scr_source` 去重）。

UNDO 一扫：`checked = checked - :q WHERE checked >= :q`，不足返回 42214 `reason=OVER_REVERSE`。

### 6.2 复核提交
1. 复核单条件更新到 PASSED 或 FAILED（`mismatch_count` = checked ≠ expected 的行数）。
2. PASSED：同事务推进出库单 T12，`outbound_order.checker_id = checker_id`（库层 `ck_ob_sod` 再兜一次）。
3. FAILED：响应 42211 `CHECK_QTY_MISMATCH`，`detail.lines[] = {line_no, expected, checked}`；不自动动库存，由主管选择：撤销拣货（05）或按实际数重新开单。

### 6.3 装箱、封箱
开箱（挂上本单 PASSED 复核单）→ 装明细（只在 OPEN）→ 封箱：`status='SEALED', sealed=true, packed_at, checker_id = 当前用户, weight_g`，打印箱码。
- 封箱人必须是该复核单的复核人，否则 40930 `detail.reason = SEALER_NOT_CHECKER`；没有权限例外（主管也不能代封，换人只能作废复核单重新复核）。
- 本复核单下所有有效箱按 SKU 合计不得超过复核量，超了 42211（库层 `box_over_check`）；封最后一箱时应用层再核"合计 = 复核量"（不足时 42211，库层只兜"不超"）。
- 封箱后改明细、改重量、改封箱人返回 **40937** BOX_SEALED_IMMUTABLE；要改只能主管解封（SEALED→OPEN，写 `audit_log`）。

### 6.4 集货
扫箱码 + 集货位码：`SEALED → STAGED`，写 `stage_location_id`。集货位温区与 SKU 温区不符返回 **42215** `STAGING_TEMP_ZONE_MISMATCH`，`detail = {location_code, location_temp_zone, sku_temp_zone}`。出库单全部有效箱 STAGED 后推进 T14。

### 6.5 发货交接
```mermaid
sequenceDiagram
  participant S as 发货主管
  participant API
  participant DB
  participant O as outbox
  S->>API: POST /shipments/{code}/handover (Idempotency-Key, version)
  API->>DB: 校验：车次 CREATED；挂车出库单全部 STAGED；箱全部 STAGED；无 RETURN_PENDING/RETURN_QC 系统冻结挂在本单已拣行
  API->>API: 16 create_from_shipment(shipment_id) → waybill_id
  API->>DB: UPDATE shipment SET status='HANDED_OVER', waybill_id, box_count(=STAGED 箱数，触发器核对), handed_over_at, handed_over_by WHERE status='CREATED' AND version=:v
  API->>DB: UPDATE pack_box SET status='SHIPPED', shipped_at=now() WHERE shipment_id=:s AND status='STAGED'
  API->>DB: UPDATE outbound_order SET status='SHIPPED' WHERE id IN (...) AND status='STAGED'（T16，逐单 rowcount 校验）
  API->>DB: post_event(SHIP) 每张出库单每个已拣库存行一条（direction=0）
  API->>O: OUTBOUND_SHIPPED（11 回传上游，#6）
  API-->>S: 200 {shipment, waybill_no}
```
任一条件更新 rowcount 与预期不符 → 整体回滚，40930（`detail = {entity, id, from, expected}`）。

### 6.6 拣货后取消、短发
- **CHECKED / STAGED 阶段取消**：走 04 T20。本篇负责：作废 OPEN 复核单；箱 `SEALED/STAGED → (解封) OPEN → CANCELLED`；把已拣数量交给 04/05 生成 `return_record(source_type='CANCEL_AFTER_PICK')`，四个 PDA 字段为空（`ck_rr_source`），同事务建 `RETURN_PENDING` 冻结（02，系统冻结，手工解冻返回 40933，`detail = {hold_type, source_type, source_id}`）。
- **复核少货（短发）**：复核 FAILED 后，主管选择按实际数发货时，差额由 05 撤销拣货回冲（`REVERSE_PICK`），出库行 `picked_qty_milli` 下调，然后重新开复核单；**不在本篇直接改库存**。是否允许"复核通过但短发"见 Q3。
- 已 `SHIPPED` 不能取消，只能红冲（04）。

### 6.7 上游回传
交接成功写 outbox `OUTBOUND_SHIPPED`，payload：出库单号、上游单号、每行发货量（3 位小数字符串）、批次、箱码列表、`waybill_no`、`handed_over_at`（车牌、司机由 16 在发车事件里回传）（ISO 8601，带 `Z`）。投递、重试、对账由 11 负责（#6）。

## 8. 并发与幂等
| 场景 | 手段 |
|---|---|
| 两人同时对一张单开复核 | `uq_chk_open`；后到者读回已有 OPEN 单，复核人不同 → 40930 |
| 复核员是任一拣货人 | 应用 40312 `CHECK_SOD` + `check_picker` 触发器 `check_sod` + `ck_ob_sod` |
| PDA 重传 | `uq_check_op` 普通 INSERT + 读回比对 |
| 多扫 | 条件更新 `checked+:q<=expected` + `ck_chkl_qty` |
| 封箱与改明细并发 | 改明细带 `version`；库层 `box_sealed` |
| 两个发货主管同时交接 | `shipment.version` + 各条件更新 rowcount |
| 交接与拣货后取消并发 | 取消要求出库单 `status IN (...STAGED)`，交接要求 `status='STAGED'`，先提交者赢，后者 40930 |

## 9. 异常与补偿
| 异常 | 处理 |
|---|---|
| 交接中途 16 建运单失败 | 同事务回滚，车次仍 CREATED，可重试（同 Idempotency-Key 重放） |
| outbox 投递失败 | 11 重试；不影响 SHIPPED |
| 封箱后丢箱或破损 | 作废申请 + 审批（§7.1），箱 SEALED→VOIDED |
| 巡检 | `CHECK_BOX_MISMATCH`：SHIPPED 出库单箱明细合计 ≠ 复核通过量；`SHIP_EVENT_MISSING`：SHIPPED 单无 SHIP 事件。码值已在 02 `ck_recon_code` |

**库存镜像过期（50301 `STALE_STOCK_PAUSED`，00 §9.1）**：该仓 `stale_stock_policy=PAUSE` 且镜像过期时，暂停的是波次释放、分配等跨网点占用库存的操作；**已下发的拣货任务、复核、装箱、集货、发货交接照常进行**，因为它们只消费已有的占用与已拣货品，不新增占用。本篇接口不返回 `STALE_STOCK_PAUSED`；交接内部调用若触发了新的分配（不应发生）则整单回滚并返回 50301。

## 10. 权限
新增权限点：`outbound.check.execute / cancel`、`outbound.pack.execute / unseal`、`pack.box.void.request`（复核员、仓主管）、`pack.box.void.approve`（仓主管、CENTER_OPS；不能自批）、`outbound.stage.execute`、`outbound.ship.plan / handover`；箱查询用 `outbound.order.view`。`unseal`、`check.cancel`、`ship.handover`、`pack.box.void.approve` 写 `audit_log`。全部受仓数据权限约束（40311）。
